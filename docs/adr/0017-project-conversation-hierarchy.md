# ADR 0017：项目与对话的层级和持久化

- 状态：已接受
- 日期：2026-08-24

> 4.5-C 更新（2026-08-24）：Agent 执行事实、工具记录、usage 与最终消息已迁到 [ADR 0022](0022-research-agent-harness.md) 定义的服务端 Session Store。本 ADR 只继续定义项目层级、会话目录和历史浏览语义，不再定义消息真相源。

## 背景

此前左侧栏使用一个原生项目下拉框，并展示两条写死的“最近”记录。Chat 消息只保存在浏览器内存中，项目切换、会话切换、刷新和应用重启无法形成一致的科研历史。

## 决策

采用明确的 `工作区 → 项目 → 对话会话 → 消息` 层级：

- 项目是所有科研视图的一级作用域。
- 每个项目拥有独立的会话列表和当前会话选择。
- 点击“新对话”只建立空白草稿；发送第一条问题时才创建会话，避免空历史污染。
- 会话标题由第一条用户问题生成，消息和会话元数据写入现有 SQLite 知识库。
- Chat 流式执行仍由 Pi Runtime 负责；持久化层只保存最终用户消息和 Agent 消息，不保存完整工具大输出。
- 项目切换器展示名称和研究问题；对话历史仅展示当前项目的会话。

## 替换边界

`KnowledgeService` 暴露稳定的会话和消息 CRUD，未来可以替换为独立同步服务，而不改变 Pi Runtime、Chat UI 或项目域模型。会话消息记录不承担 Artifact、证据和科研溯源职责；这些对象继续通过各自结构化存储管理。

## 验证

- Knowledge smoke 覆盖会话/消息写入、重启恢复和项目隔离。
- Server integration 覆盖会话 API 和跨项目 Chat 拒绝。
- 浏览器验收覆盖新对话、自动标题、历史刷新、页面刷新恢复和项目切换隔离。

# ADR 0020：上下文正确性风险加固

- 状态：Accepted
- 日期：2026-08-24
- 范围：Pi Runtime、Context Broker、Skill 激活与宿主缓存

## 背景

汐灵 OS 已具备按活动画布分支投影、持久化 Capsule、动态能力与 Skill 激活、模型窗口自适应装配。架构复核发现，一些问题会直接改变科研对话所见的证据或导致错误的会话序列，属于发布前必须处理的正确性风险；另一些问题只是规模化后的维护或检索优化，不应在当前阶段提前增加复杂度。

## 立即处理

1. 分支 Capsule 不再只抽取首、中、尾节点，必须逐节点保留可追溯摘要与关键声明。
2. 历史消息先规范化为完整的 `user → assistant` 回合，再从最新回合连续回溯；不得跳过超大中间回合后又加载更早消息。
3. 当前用户问题计入模型输入预算，并进入缓存身份；项目与会话也纳入缓存命名空间。
4. 传给模型的 Skill 包装只使用稳定的 `skill://name@version` 标识，不暴露宿主绝对路径。
5. Context Assembly Cache 同时限制条目数和估算 token 总量，使用 LRU 淘汰。

这些修复优先保护科研证据完整性、会话协议有效性、预算真实性、隐私边界和服务内存稳定性。

## 暂缓处理

- SQLite 正式迁移框架：当前 schema 仍可幂等创建，尚无多版本部署压力；首次出现破坏性 schema 变更前必须引入。
- 语义能力路由：当前能力目录规模小且核心工具具有精确映射；在误路由数据证明关键词路由不足前，不引入 embedding 或额外模型调用。
- MCP 接入：不属于本次范围，保持未接入状态。

## 验证

自动化测试覆盖完整分支 Capsule、有效回合序列、连续历史选择、固定输入超窗、Skill 路径脱敏、缓存 token 上限。服务指标暴露缓存条目数与估算 token 总量，但不暴露原始提示或凭据。

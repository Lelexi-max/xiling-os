# ADR-0004：科研画布采用 Flowith 式 Context Playground

- 状态：已确认并实施
- 日期：2026-08-23

## 背景

上一版原型将科研对象展示成预先定义的 DAG，接近工作流编辑器。这不符合 Flowith 的画布交互：输入和回答本身成为节点，用户可从任意节点继续、分支或跨节点引用，Agent 计划与产物在执行过程中动态长出。

## 决策

XYFlow 只承担无限画布基础设施。产品语义改为：

- Follow-up：从一个节点的祖先分支继续；
- Quote：显式组合多个节点形成新上下文；
- Free Node：不触发模型的手工内容；
- Batch Branch：同一输入并行产生多个方法或模型分支；
- Recipe：Agent 动态计划、工具节点、结果和检查点；
- Restart from Checkpoint：保留上游结果，从某点重建下游。

节点位置与语义拓扑严格分离：

- 拖动节点只修改画布坐标，不修改上下文；
- Follow-up、Quote、Produced、Checkpoint 边只由对应的产品动作或 Agent 运行产生；
- 不允许用户通过任意拖线隐式改变模型上下文；
- Composer 必须显示当前 Follow-up 锚点、祖先节点数和显式 Quote 集合；
- Chat 与 Canvas 共用持久化的 `CanvasBranchContext`，切换视图后恢复相同活动分支。

## 科研适配

节点不仅包含文本，还可包含论文证据、数据摘要、代码、Run、图、表和结论。科研溯源边与对话延续边分离，避免把“引用证据”误认为“执行依赖”。

## 结果

- Canvas Context Resolver 成为核心自研模块。
- 项目不提供传统拖节点配置工作流作为首版主体验。
- 画布的分支拓扑同时成为上下文选择机制，减少无关历史进入模型。
- 已经由画布投影带入的 Chat 消息不再从“最近会话记录”重复装载。

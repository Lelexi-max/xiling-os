# ADR 0037：统一真实模型路由与角色级覆盖

- 状态：Accepted
- 日期：2026-08-28
- 取代：ADR 0010 中的产品 `offline/live` 双模式

## 背景

把离线演示当作产品运行模式，会让用户误以为未配置模型时仍在执行真实科研 Agent，也使设置页同时承担连接、费用确认、模型能力和运行开关，层级混乱。单一全局模型还无法满足检索、领域执行与独立审查之间不同的成本、上下文窗口和推理需求。

## 决策

1. 产品运行时只有真实 Provider 路由。没有可用主模型时正式 Agent Run 明确失败，不能静默返回 fixture 内容。
2. `ModelRuntimeStore` 持久化主智能体路由和角色专属路由。未配置专属路由的子智能体继承主模型。
3. 模型解析优先级固定为：Chat 本轮覆盖 > 子智能体角色专属路由 > 主智能体默认路由。本轮覆盖写入 Run context 以便重放和审计，不修改全局默认值，也不传播给隔离子智能体。
4. 模型连接与模型分配分离：API 连接页只管理凭据和最短连通测试；模型分配页管理主模型、推理强度、原生模态与子角色路由。
5. Pi 离线 stream 仅作为显式注入的测试适配器存在。它不出现在设置契约、产品 API 或界面中，也不能由用户启用。
6. 原生输入能力按实际选中模型计算。切换模型时，Chat 附件入口同步启用或禁用；不支持的模态不得转写、抽帧或降级伪装。

## 约束

- API Key 不进入 `model-runtime.json`，只由 `CredentialStore` 保存。
- 角色路由受同一凭据检查、能力验证与 TokenLedger 记录约束。
- 自定义模型允许自由输入 ID；未知图像能力仍需真实原生探针。
- 测试必须证明产品契约中不存在离线模式，缺少主模型时正式 Run 会失败，角色路由可持久化恢复。

## 结果

模型配置从“开关一个模式”变为“声明一组可审计路由”。这使多智能体成本治理和模型专业化成为宿主层能力，同时保留 Pi Provider/Agent 适配边界，未来升级 Pi 时不需要改 Chat、Harness 或科研图契约。

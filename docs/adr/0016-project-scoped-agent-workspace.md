# ADR 0016: 项目作用域的 Agent 科研工作区

## 状态

已接受，2026-08-24。

## 背景

Gate 4 的 Chat、画布、项目、Wiki、文献图和证据库已分别具备纵向样例，但前端项目选择由各视图自行维护，服务端画布文件与证据接口默认写入 `ocean-heatwave`。Pi 只承担模型流式传输，初始工具数组为空。这会造成跨项目数据串线，也无法让一次研究任务跨越文献、数据规划和知识沉淀。

## 决策

- `WorkspaceProvider` 是前端唯一活动项目状态源；项目切换立即投影到 Chat、画布、项目、Wiki、文献证据和页面标题。
- 所有领域读写显式携带 `projectId`。画布按项目哈希分文件持久化；旧默认项目布局只作为兼容读取来源。
- Chat 会话、运行状态和消息按项目隔离，不把一个项目的对话或示例 Artifact 显示在另一个项目。
- Chat 请求携带 `projectId`；服务端校验项目存在且未归档，再建立项目级系统提示和投影哈希。
- Pi 初始仍不常驻全部工具。宿主根据用户提示从短目录中激活最多四项能力：项目摘要、文献检索、Wiki 读取和海洋数据切片预检。
- 工具结果只返回结构化短摘要。论文全文、完整引用列表、数据和日志不进入 Agent 上下文。
- 文献检索、项目读取和切片预检可以直接执行；下载、计算、审批和知识写入不得由 Agent 静默执行。
- Assistant 回答只有在用户点击确认后，才可保存为项目任务、Wiki 页面或画布 checkpoint。

## 安全与替换边界

- `selectResearchTools()` 是能力发现策略边界，后续可替换为语义路由或 Skill 索引而不改变 Pi 工具协议。
- 数据切片工具只调用纯预检，不探测实时体积、不创建审批单、不下载。
- 写入操作沿用现有领域 API；Chat 仅提供显式确认按钮，不赋予模型直接写权限。
- 项目归档后，Chat 请求返回 404，避免继续向已关闭上下文写入。

## 验证

- 两个项目的 Wiki、证据和画布隔离测试。
- 不存在或已归档项目的 Chat 拒绝测试。
- 按提示词动态激活工具且不超过四项的测试。
- 浏览器验证项目切换同步五个视图。
- 浏览器验证 Pi 调用项目、文献和切片预检工具。
- 浏览器验证用户确认后同一回答进入任务、Wiki 和画布。

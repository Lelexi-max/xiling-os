# ADR 0015: 可扩展多模态模型连接器

## 状态

已接受，2026-08-24；原生图像输入实现补充于 2026-08-25。

## 背景

原实现只允许四个写死的模型提供商，且把“凭据已保存”误当成“模型可调用”。Pi 的 Provider 失败通过流协议返回；若宿主只映射文字增量，错误会表现为空响应。与此同时，多模态能力属于具体模型和端点，不能由提供商名称静态保证。

## 决策

- 复用 Pi 0.84.2 已有 Provider 适配器，首批暴露 OpenAI、Anthropic、Gemini、OpenRouter、DeepSeek、xAI、Mistral、Moonshot、z.ai 与 Groq。
- 提供一个 OpenAI Chat Completions / Responses 兼容连接，覆盖 vLLM、Ollama 与企业网关；Base URL、协议、测试模型和密钥均进入现有 AES-256-GCM 凭据存储。
- Provider 卡不再展示或暗示模态能力。模态只出现在具体模型配置区；真实请求以“具体模型能力 ∩ Pi 内容块协议”为准。
- 保存凭据不代表可用。模型卡提供最短文字生成测试，返回模型、延迟和脱敏错误；测试内容不进入科研项目或 Agent 上下文。
- Pi 的 protocol `error`、空文本结束和取消必须转换为 `session.error`，前端不得把它们显示为成功完成。
- 推荐模型目录每个 Provider 最多返回两个候选，避免设置页和后续 Agent 上下文无界增长。完整模型发现后续按需请求，不常驻上下文。

## 多模态路由原则

- Artifact-first 指原始媒体只存储一次并获得稳定 URI、哈希与溯源信息，不表示必须先转录或抽帧。
- 当前 Pi 0.84.2 标准内容块只支持文字与图像。已知模型采用 Pi 目录声明；目录外模型默认仅文字，只有发送最小原生 PNG 探针成功后才持久化图像能力。音频、视频在 Pi 提供原生内容块前不可开启。
- Chat 与科研画布共用同一上传协议。每轮最多 4 张、单张 8 MB、合计 20 MB，仅接收 PNG/JPEG/WebP/GIF；服务端校验 MIME、文件签名、长度和 SHA-256。
- 小型输入图像以项目作用域 BLOB 存入 Agent Store，并在对话记录中只保存描述符、哈希和耐久附件 ID；base64 只在浏览器上传边界和 Pi 请求适配边界短暂存在，不写入消息正文、工具结果或压缩摘要。
- 当前轮图像总是原生发送。历史图像不随全部历史机械重发；只有用户明确引用上一张/此前图片时，Context Broker 才从最近的相关用户回合恢复一组图像字节。其他回合仅带入“附件名 + 本轮未重复载入”描述。
- 严格执行 Native-only：模型未明确支持的输入或输出模态在 UI 和 API 层直接禁用并拒绝请求，不使用转录、OCR、抽帧、代理媒体或其他非原生方式模拟支持。
- 能力解析以 Pi 具体模型目录或服务端原生探针为准。模型页展示来源 `PI CATALOG`、`NATIVE PROBE` 或待探测状态；不存在非原生降级模式。
- 原生输入产生的回答必须记录 Provider、模型、媒体参数和远端文件句柄，使调用可复现。

## 边界

- 本 ADR 当前落地图像输入闭环。音频、视频输入以及图像输出仍等待 Pi 上游拥有对应原生内容块；不得用转写、抽帧、OCR 或代理模型绕过。
- 当前附件存储面向受限的小型交互图片；大型科学影像、视频和长期复用媒体仍必须进入 Artifact/Object Store，不应扩张 Agent Store BLOB 上限。
- 自定义连接目前提供一个本地配置槽；多配置实例化将在连接注册表持久化后扩展。
- Provider 能力标签是上限说明，不是对任意模型的能力承诺。

## 验证

- Pi 错误协议映射测试。
- Pi 原生图像内容块透传测试。
- 图片字节/描述符/哈希写入、重启恢复与项目作用域读取测试。
- 模型与 Pi 不共同支持图像时的服务端拒绝测试。
- 未经探针验证的目录外模型不能持久化图像能力测试。
- 凭据加密与自定义端点恢复测试。
- 服务端与前端类型检查。
- 全量离线测试和 Web 构建。
- 设置页连通测试与 Chat 错误呈现的浏览器端到端验证。
